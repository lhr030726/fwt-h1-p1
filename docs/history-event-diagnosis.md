# 下一轮修改的证据边界

2026-10-27，本地只读检查了 1379 个 Tr/V 输入数组，读取原始火场通道，按冻结
配对规则重新计算历史变化。逐样本计数与最终服务器 history-audit 相符。
没有访问最终测试集，也没有根据验证事件生成训练权重或门控规则。

全部 1173 个历史配对没有负变化像元、零变化配对或无效像元，不能把这次
退化归因于正负池化抵消或缺失像元稀释。仍保持 signed 输入兼容原协议。

70 个有历史事件中，56 个 AP 改善、14 个退化；14 个中 12 个在全部三个分支
种子下都退化。因此需要检查系统性偏差，不能只归因为随机初始化波动。
例如 2015_UID_320 有一天配对历史，变化360像元，末五轮三种子平均 AP 从
0.8311 降到0.2485。这是错误分析示例，不能用于指定该事件回退或剔除。

退化事件的日均变化像元中位数357，改善事件814.3；配对日数中位数分别2和5。
这些是看过开发结果之后的描述关联，不是可直接作为预测规则的因果结论。
V 非空4×4池化单元中8.28%只有一个变化像元，14.52%最多两个，说明存在
稀疏幅值衰减；但没有反事实消融证明它是退化来源，本轮不叠加池化结构修改。

现有监督按事件时长/像元数贡献不均，与事件均权评价不同，这是代码层面
可以直接核实的差异。本轮只检验事件混合损失及受限修正两个因素。
尚不能从现有汇总日志区分错位、观测噪声、短历史与后续蔓延失配、空间平滑
或过度修正等原因。新增逐事件/样本修正量和 proper-score 诊断用于下次定位。

完整逐事件数据、输入统计、可复现只读脚本及源文件 SHA 保存在本次工作区的
`outputs/performance/history-refiner-next/diagnosis/`；此前训练日志和权重仍在
GitHub 的 `rescue-history-refiner-20261026` Release，不改写既有结果。
